# 曹操传加速补丁：6.4 / 6.5 / 6.6

本项目保存曹操传加速补丁源码和支持 6.4 / 6.5 / 6.6 的单文件安装器。源码包含阶段加速、超级加速、齿轮模块、简易攻略、战斗统计、存档统计持久化、安装与卸载逻辑及对应离线测试。


## 1.4 Release（1.4.0）

下载：[v1.4.0 Release](https://github.com/Artkights/cao-cao-mod-6.6-speed-patch/releases/tag/v1.4.0)。更新内容见 [更新说明-1.4.0.md](更新说明-1.4.0.md)，实机检查可使用 [实机验收-1.4.0.md](实机验收-1.4.0.md)。

本版修复大明 6.6 加壳 EXE 因磁盘文件超过 64 MiB、壳 raw 数据远大于虚拟节而无法安装的问题，加入共享 PE 访问层、运行时稳定等待和原生导入能力解析。保留此前对信奈基底保存时被误判为缺少 `.EXS` 而回滚的修复。保存逻辑依据实际原生保存/读取调用图区分 E5S 单文件存档和 E5S/EXS 配套存档，不能从“6.6”版本号推导必须存在扩展文件。

本地源码现支持 6.4、6.5、6.6 三代引擎，按功能安装、可审计自适应注入、事务恢复及统计 schema 4。正式构建使用 `source/build-dual.ps1 -Tests`，安装器位于构建目录的 `package` 子目录。外部 `源码-20261015` 仅作为迁移参考，不属于本仓库。

- 安装器显示“加速、简易攻略、战场统计”复选框；更新时默认当前组合，卸载时选择要移除的功能。游戏内卸载入口使用相同的选择界面，退出游戏后由卸载助手执行。任一功能存在时保留共享音频代理，只有卸载最后一个功能才恢复原始 DLL。
- 命令行支持 `/install /features=accelerator,guide,battlestats` 和 `/uninstall /features=guide`。安装参数指定目标组合；卸载参数指定移除集合。`/quiet` 省略功能参数时沿用旧版全功能行为，未知引擎不能以静默模式强制安装。
- 自动检测以 PE 节映射、唯一上下文签名、调用关系和已验证 ABI 为依据。`patch\xiaoan64|65|66\engine-plan.txt` 记录 RVA、文件偏移和原始字节；自动识别失败时不会误报已验证；用户可按下一项明确确认版本回退，运行时仍检查可执行页、捕获原始字节并保留恢复记录。
- 无法静态确认的引擎可显示版本回退警告；用户明确选择 6.4、6.5 或 6.6 后，安装器先备份 `Ekd5.exe`、音频 DLL、Gear、配置和功能状态，再按版本模板进行运行时注入。能自动识别的加壳构建仍使用自动计划。版本回退不向 `Ekd5.exe` 写入固定偏移，卸载仍按清单恢复原始文件。
- 加强版 2.2.0 的受保护构建会登记为 `Protected220`，安装后等待保护层展开，验证原生导入槽、虚拟文件入口和 6.5 运行时布局后才启用可选模块；磁盘保护区不会被直接写入。
- 受保护 2.2.0 的简易攻略不把保护层返回的虚拟句柄当作普通 Win32 文件句柄。攻略从当前进程已经加载的人物表（1024×`0x48`，姓名 `+8`）和物品表（255×25，`Data`/`Star` loader 关系）取得名称，物理 `Data.e5`/`Star.e5` 只作补缺；运行时名称读取使用实际页权限、对象标签、双快照和严格 GBK 校验。资源表尚未就绪时后台最多等待 30 秒，仍保留“武将/道具 ID”占位和诊断，不静默删除对话、伏兵、AI 或奖励。
- 卸载会验证首次备份及当前代理、原音频副本和齿轮文件。外部替换导致冲突时停止，保留现有文件与备份。私有目录中用户后来新增的无关文件保留；只移除补丁拥有的配置、计划和清单。
- 攻略窗口只保留一个固定宽度的剧本选择框，始终显示全部内容；右侧分类下拉框和“重新读取”按钮已移除。剧本选择、字体大小、行间距和导出按钮位于同一行；窗口最小尺寸为 700×240 DIP。字体 `FontHeightTwips` 默认 220（范围 80–640），行间距 `LineSpacingTwips` 默认 45（范围 0–400，对应 RichEdit 段后距）。配置在各引擎私有目录的 `guide-ui.ini` 中原子保存，完整卸载时移除。
- 战场统计采用独立 schema 4，继续读取 schema 1/2/3 并把旧档新增受击字段初始化为 0，同时标记 `historyIncomplete=true`。统计按真实物理/策略攻击段和真实闪避观察采集，免疫、未造成伤害和多段攻击均按实际调用链计数；无法验证的指标显示 `--`。schema 4 额外保存全局加入名单、当前战场出战集合、阵营变化和历史完整性。战场离场时在私有 `records` 目录写入 UTF-16 TXT 与转义 CSV，并将保存、迁移、导出和能力状态写入 `diagnostics/stats.log`。
- 简易攻略的能力编号 7、8 统一显示为“HP上限”“MP上限”，并对 0x38 能力设定命令支持提升、下降、设定及未知操作的可审计文本；R 场景奖励命令会与跳转的 S 场景内容合并。
- Protected220 的 `0x7B` 条件作为独立能力解析：保留原始文本条件，支持五个分支和三处子事件继承，条件去重包含文本内容；它与运行时名称 provider 分开门控，当前 2.2.0 证据为 48 条原始条件、96 条继承关系和 48 条状态动作。
- 统计窗口提供当前战场/全局页签、十列统计、64 位数值和表头排序；定时刷新保留排序方向与滚动位置。统计模块只在 `FeatureBattleStats` 启用时初始化，攻略和加速可独立运行。
- 加速核心针对 6.4 阶段回调、超级加速等待桥和 PE 站点扫描做了低风险性能优化：减少无用内存读取、重复时钟采样与浮点换算，并使用固定字节锚点加速签名搜索。未知或歧义调用会安全降级，偏移变化 MOD 仍需通过 EnginePatchPlan 验证。

存档适配将 `Unsupported`、`None`、`Verified` 分开处理：信奈 15+1 和 12 关样本识别为 `None`，只事务保存实际 E5S；完整验证了原生扩展保存与读取调用图的样本为 `Verified`，继续强制校验配套 EXS。图谱歧义或保存/读取不对称时拒绝覆盖。信奈的普通保存能力与回合自动保存边界分别判定，当前两个信奈样本未确认回合自动保存边界。

保存事务日志 schema 2 使用 `Prepared`、`Committed`、`Restored` 三种持久状态。恢复先验证完整备份集，再恢复整组文件，刷新 `Restored` 标记后才清理备份；已提交或已恢复的日志只做清理。启动恢复失败时保留已验证的保存/读取保护入口，每次操作先重试恢复，避免绕过未完成事务。`CleanupPending` 表示保存组已确认但清理待重试，本次提交可报告成功；后续操作先完成清理，能力状态同步显示待清理原因。

每次保存使用独立操作标识，原生调用在到达文件名入口前失败也不能沿用上一次成功。只有本次原生返回与本次事务提交均确认，才更新轮换索引、时间和截图。保存回滚会记录具体阶段，不把仍完整的统计历史标成丢失；旧档解码、模型迁移和原生读档结果分别报告，存在但损坏的统计块不会被显示成“无历史”。

schema 1 清单在升级时视为三个功能均启用，并保留首次备份。旧版安装器和旧版卸载助手不支持 schema 2；升级后应使用本版本安装器或本版本游戏内卸载入口。游戏存档、作者攻略文本和用户新增文件不作为卸载的删除对象。

## 加壳构建与运行时状态

- 磁盘文件长度使用 64 位值，SHA-256 分块计算；64 MiB 限制仅用于分析映像容量。非零 `VirtualSize` 决定节的逻辑虚拟范围，零值才回退到 raw 长度；超出虚拟范围的壳容器不参与代码扫描，仍参与整文件指纹与安装前备份。
- 大明 6.6 已通过只读样本检测：EXE SHA-256 `F9F0E30C8926949ECC0B1B4A03DE3DFDCFEA3E3923C23773C3013C9763F4144B`，自动识别 6.6、13 个唯一签名、17 个等待调用者。此结论仅是静态检测通过。
- 代理的 DLL 加载入口只创建后台工作线程；扫描、哈希、轮询、Gear 加载和模型初始化均在加载锁外执行。后台按 100 ms 间隔检查，布局和导入连续两次稳定后提交，启动等待上限 15 秒；游戏线程不等待后台检测。
- 原生入口按文件、消息和时钟分别识别。公开表、残留原生表及 OFT 缺失表均需实际调用关系和已提交页面验证，重复候选不盲选；文件包装器保留捕获的原目标。无法确认的时钟包装器不被系统入口替代，齿轮会停用，其他已确认加速能力保留。
- 安装清单 schema 2 的 `[Compatibility]` 保存 `Container`、`Layout`、`Startup`、`Accelerator`、`Guide`、`Stats`、`Detail`。安装完成时各模块为 `Pending`，只有实际初始化之后才写入 `Ready`、`Partial` 或 `Unsupported`。`RuntimeValidation` 表示磁盘身份、展开布局及原生入口验证结果；它不能代替各模块状态。
- 保护层展开前的场景和统计事件不可追溯。本版不从静态剧本补造实际事件；加壳构建的统计历史明确标记不完整，状态为 `Partial`。不可确认的指标继续显示 `--`。
- 运行时只合并报告一次尚未就绪项目，详情在 `patch\xiaoan64|65|66\diagnostics\runtime.log`。安装器 `/diagnose="<游戏根目录>"` 只读输出检测结果和上次记录的状态，不启动游戏。普通启动仍是双击原 `Ekd5.exe`，不提供专用启动器、不解壳或重打包 EXE。

## 构建

在 `source` 目录打开 Windows PowerShell 5.1 或 PowerShell 7，执行：

```powershell
.\build-dual.ps1 -Tests
```

脚本通过 Visual Studio 2022 Community 的 `vcvars32.bat` 初始化 x86 工具链。`build.cmd` 执行普通构建，`build-tests.cmd` 构建三版载荷及测试程序。`build-dual.ps1 -BuildDirectory <目录>` 可把 `common`、`64`、`65`、`66` 和 `package` 全部输出到仓库外的独立目录，避免把可重建产物写入 Git 工作树。

`-Publish` 会复制安装器到开发目录外的发布路径，源码归档和离线验证时无需使用。1.4 Release 按用户决定以完整构建和离线回归作为发布条件；游戏实机验收由用户完成，发布不代表所有加壳 MOD 已通过实机认证。

## 离线验证

`GuideBookFileTests.exe` 在临时目录创建最小剧本和文本，验证编码、作者攻略优先、按关回退、全量导出和替换失败保护；`GuideWindowTests.exe` 使用真实攻略窗口验证单行工具栏、原生排版参数、异步导出以及覆盖确认/取消。两者均无需游戏基底，已加入双版本测试构建与验证脚本。`GuideWindowHarness <game-pid>` 默认只检查运行中游戏的攻略界面；仅显式传入 `--export` 时才确认覆盖并执行导出，应对隔离游戏副本使用该选项。

回归测试需要本地持有三套游戏基底（6.4、6.5、6.6）。仓库不分发游戏本体、剧本、数据文件或测试游戏副本。先完成上述 `-Tests` 构建，再在 `source` 目录显式指定三套基底、仓库外构建目录及隔离输出目录：

```powershell
.\verify-dual.ps1 `
    -BuildDirectory 'D:\CCZ\build-1.4.0' `
    -GameRoot64 'D:\CCZ\洗隋' `
    -GameRoot65 'D:\CCZ\加强版6.5未加密版' `
    -GameRoot66 'D:\CCZ\复刻版6.6山贼 国庆' `
    -GameRootNobuna 'D:\CCZ\信奈15加1' `
    -GameRootNobuna12 'D:\CCZ\信奈12' `
    -GameRoot220 'D:\CCZ\加强版2.2.0' `
    -GameRootPacked 'D:\CCZ\大明6.6' `
    -RuntimeImage220 'D:\CCZ\evidence\protected220-current.rva.bin' `
    -OutputDirectory 'D:\CCZ\verification-1.4.0'
```

三套基底需要相应的 `Ekd5.exe`、游戏数据与测试剧本；6.5 基底需原始音频 DLL（优先取 `Koeicda_org.dll`，不存在时取未安装基底的 `Koeicda.dll`，也可用 `-OriginalAudio` 指定；测试会核验其确为原始实现），6.6 基底还需 `ExtendData.dll`。脚本只读取基底；安装事务与故障回滚测试在隔离目录内执行。日志及 `results.json` 写入指定输出目录，测试程序和构建产物不属于发布内容。

已验证为 EXS 配套格式的原生扩展存档校验需要对应 6.6 基底 `SV` 目录中至少七个 `.EXS` 样本，并逐一校验目录中所有样本；存在额外存档时继续覆盖这些样本。

## 简易攻略文件与导出

简易攻略窗口优先读取游戏根目录（补丁 DLL 所在目录）的 `简易攻略.txt`。文件不存在、为空、无法读取，或当前战场没有非空正文时，自动根据对应 S 剧本生成当前关攻略。选择 R 剧本时，继续使用其跳转到的 S 战场编号。作者正文保留空行和缩进；作者攻略与自动生成攻略都直接显示完整内容。外部编辑保存文件后，关闭并重新打开攻略窗口即可读取修改。

文件用独立一行的关卡标题分段，编号对应 S 文件编号，支持 `0` 到 `999`：

```text
第 00 关简易攻略
作者自定义的零关攻略。

第 01 关简易攻略
作者自定义的一关攻略。
```

读取兼容 `第00关简易攻略` 这样的无空格标题、UTF-8（有无 BOM）、UTF-16LE BOM 和 GBK。重复编号以最后一段为准；最后一段为空时该关回退自动生成。首个有效标题之前的文字忽略。整行符合标题格式的文字作为分隔符，请勿在正文中重复使用。单份攻略文件上限为 64 MiB，损坏或超过上限的文件按读取失败处理。

点击“导出攻略”会重新扫描 `RS\S_*.eex`，将所有非空、可解析的 S 剧本按编号生成到根目录的 `简易攻略.txt`，使用 UTF-8 BOM 和 Windows CRLF 换行。空脚本不导出；损坏或不可读的非空脚本跳过并报告关卡编号。相同编号只生成一段，优先有效的规范文件名（如 `S_02.eex`），其次按文件名排序选择有效别名。

导出始终使用自动生成内容。目标文件非空时会提示确认覆盖作者原稿；取消保留原文。导出在后台执行，成功后立即刷新当前关卡，失败保留原文件及页面内容。写入采用同目录唯一临时文件、刷新磁盘和原子替换；没有可导出剧本时也不会覆盖现有文件。

`-GameRoot64`、`-GameRoot65`、`-GameRoot66`、`-GameRootNobuna`、`-GameRootNobuna12`、`-GameRoot220`、`-GameRootPacked`、`-RuntimeImage220` 和 `-BuildDirectory` 均可显式指定。独立克隆建议全部传入参数。

## 验收边界

离线回归已覆盖 6.4、6.5、6.6 的引擎布局、EnginePatchPlan 偏移映射、受保护 2.2.0 指纹和运行时导入桥、FeatureMask 八种组合、统计 schema 1/2/3 迁移、受击/闪避故障注入、TXT/CSV 导出、诊断日志、十列表格排序、攻略参数持久化以及安装事务回滚。验证脚本本身不会修改游戏基底，构建和日志应放在仓库外。

1.4 Release 的真实游戏启动、保存、关闭、重启、读档、统计逐字段对照和偏移变化 MOD 由用户实机验收；可使用隔离副本，或按用户明确授权在已备份的原基底测试，记录实际 EXE、载荷及进程身份；本仓库不把未执行的实机流程标记为已验收。候选安装器由 `source/build-dual.ps1` 生成到指定的仓库外 `BuildDirectory`，`main` 中源码不包含可重建产物，安装器与源码包随对应 Release 单独分发。
