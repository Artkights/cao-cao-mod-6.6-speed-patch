# 加速补丁安装器：6.4 / 6.5 / 6.6

本目录是在原有源码基础上实施的三代引擎适配。1.4 Release 分发单文件安装器、源码归档、说明、校验值和离线验证记录；游戏副本与测试存档不分发。

## 使用

退出游戏，把安装器放入含 `Ekd5.exe` 的游戏根目录，双击运行。也可以显式指定目录：

```text
加速补丁安装器.exe "游戏根目录" /install
加速补丁安装器.exe "游戏根目录" /uninstall
加速补丁安装器.exe "游戏根目录" /install /quiet
```

无目录参数时使用安装器自身所在目录。命令行选项、返回码及游戏内操作方式沿用原程序。配置仍为原有 74 行加速配置，功能设置单独保存。首次安装保留原始文件备份；升级保留首次备份和用户配置。卸载可通过安装器或游戏菜单发起。

安装器分别保存 6.4、6.5、6.6 三套音频代理 DLL，并按引擎调用布局与版本资源选择。通过布局校验的标准和加壳 MOD 均优先走自动计划；无法唯一识别的目标会显示版本回退警告，用户明确选择版本后先备份相关文件，再按该版本模板进行运行时注入。版本回退不修改 `Ekd5.exe` 的磁盘代码，只在进程展开映像中保存原字节并写入补丁；安装清单和卸载事务保留完整恢复记录。加强版 2.2.0 在精确保护构建指纹匹配后登记为 6.5 `Protected220`，并在保护层展开后进行受限运行时验证。

## 源码结构

- `EngineProfile.*`：磁盘 PE 和运行中映像的版本识别、调用图复核、主程序 SHA-256、统一私有路径。
- `EngineLayout.*` / `Engine.cpp`：三代布局、逐站点模板、原生调用约定、事务写入和恢复。6.4/6.5 阶段调用传递 ECX，原生超级加速按各自站点集合解析；6.6 继续使用七个站点。
- `Proxy.cpp`：核心初始化依次启用运行时、统计模型、事务恢复、场景监听和存档监听；早期消息和普通文件调用在加载器回调之外等待就绪。R/S 文件打开只提供资源观察，不驱动统计清零。
- `SaveEnhancer.*`：公共原生保存入口、写入/关闭结果、成功提示前提交、原生读档入口与同步完成恢复；首尾轮换、截图、备注和浏览继续使用原有入口。统计保存不依赖回合自动保存布局全部可用。
- `SaveTransactions.*`：E5S 临时文件、EXS 新鲜度、备份、持久事务日志、失败复原及跨进程读写互斥。6.4/6.5/6.6 已验证的普通档、原生自动档、补丁轮换档共用此链路。原生扩展要求由实际保存/读取图决定，不由编译版本决定。
- `ScenarioLifecycle.*`：验证实际剧本安装调用链，以原生序号、调用来源和加载事务区分新游戏、新 S 实例、同 S 重装及读档。
- `ScenarioScript.*`：公共 EEX 解码、条件继承、参数标签与命令位置，用于攻略和旧档 R 剧本名单推断。静态候选不作为新档加入证明。
- `Guide.*`：运行时名称优先、物理名称表补缺和缺名诊断。Protected220 使用 BattleRuntime 的自有字符串快照；资源 provider 与 `0x7B` 条件扩展分别门控，读取任务在运行时表发布前按 500 ms 间隔重试，旧任务不能覆盖新请求。
- `BattleRuntime.*`：运行时扫描按 `VirtualQuery` 的实际提交页枚举代码，签名不能跨不可读空洞；人物表按 `0x48` 行和 `0x1000 + id` 标签校验，物品表按唯一 `id*25` getter、Data/Star loader 和 `0xED8` Star 读取长度校验。ProtectedRuntime 目前只验证导入桥和游戏自己的虚拟文件转发，没有通用 VFS reader。
- `BattleRosterRuntime.*`：验证 0x3B 分派、参数解码、R/S 分支与人物阵营写入关系，观察成功返回并轮询人物总表，通知实际加入和阵营变化。
- `BattleStats.*` / `BattleRuntime.*`：按版本解析事件来源，以人物编号分别维护当前出战集合、全局加入名单和两组账本；按参与者及追踪状态门控每次结算，不在战斗结束后重复追加。
- `BattleStatsPersistence.*`：在 E5S 尾部写入 schema 4 统计块，保存两组数据、战场身份、累计时长、受击/闪避能力、全局加入名单、当前出战集合和覆盖状态，分别校验原生数据与统计内容。兼容读取 schema 1/2/3 及旧哈希匹配 `.stats`，标记迁移历史不完整。复制或改名 E5S 会携带内嵌统计，游戏所需 EXS 仍须配套。
- `InstallCommon.*` / `Installer.cpp`：版本与安装状态分离、双载荷选择、正式写入前复核主程序指纹、保留备份、失败回滚、清单提交和卸载。

## 构建和复验

需要 Visual Studio 2022 Community 的 x86 C++ 工具链及 Windows SDK。脚本调用 `vcvars32.bat`，使用 C++17、Win32 x86、静态 CRT。支持 Windows PowerShell 5.1 和 PowerShell 7。

```powershell
.\build-dual.ps1 -Tests
.\verify-dual.ps1
```

`build.cmd` 对应普通构建，`build-tests.cmd` 构建三代测试。`build-dual.ps1 -BuildDirectory <目录>` 可把 `common`、`64`、`65`、`66` 和 `package` 输出到仓库外；`-Publish` 会把安装器复制到中性命名的发布目录，应在回归通过后使用。

验证脚本只读取原始游戏基底，安装事务在新隔离目录中执行。实机安装和运行可使用独立副本，或用户明确授权且已有备份的原基底；每次核对实际安装路径、加载的 DLL 哈希与进程路径，不能用另一个未安装补丁的同名目录代替。验收记录须区分离线调用图、真实 ABI 执行、安装闭环和实机行为，未实际执行的场景不得记作通过。

1.4 Release 发布后由用户完成三代真实游戏中的保存、关闭、重启、读取和两页逐字段对照，验证新游戏、同 S 重开、普通读档、正常跨 S 四类事件，以及原生读取带扩展块的 E5S。加强版 2.2.0 的离线 runtime-RVA、Guide 和 ProtectedRuntime 回归已经完成；真实攻略窗口仍需在新进程、手动进入战场、移除作者攻略文件、切关/读档/重新附加和全量导出场景下记录人物/物品名称、事件身份及游戏表现。当前离线测试中的独立写入/读取子进程及直接执行生产汇编桥，不替代上述实机门槛；未执行的实机流程继续明确标记为未验收。

## 1.3.3 保存与资源接口契约

`ResolveCoreLayout` 解析原生扩展保存和读取调用图后，发布 `NativeExtensionCapability`：`None` 表示本画像已证实无 EXS 参与，`Verified` 表示配对调用及 ABI 已验证，`Unsupported` 表示不能证明支持。`SaveFilename65Impl` 使用此能力创建事务。E5S-only 不创建虚构的 EXS 路径，也不触碰同目录无关 EXS；Verified 仍校验文件新鲜度、配对及原生验证结果。普通存取入口可用不等于首尾回合轮换边界已验证。

信奈 15+1 样本 SHA-256 为 `8599725B02DC2F8F5E45913B0D2F69E639694A3D59399D2A1E9D63DF42C105CE`，12 关样本为 `9E3EE0ADE22EA855FF64ACAB864D8C14B7E9E800FD5CA08C8B27D1E5CF6889BE`。两者静态及生产桥测试均识别为 6.6 / None；当前未确认回合自动保存边界。不能把此结论扩展成所有 6.6 MOD 均无扩展存档。

保存开始时重置本次 attempt 标识和原生结果观察状态；文件名、commit、result 三个桥必须属于同一 attempt。私有原生保存开始前建立标识，即使原生前置检查失败、未进入文件名桥，result 桥也不能复用旧提交。失败保留上次成功轮换记录。原生函数异常、事务中断和恢复失败均需释放本次资源，并由已安装的保护入口阻止绕过未完成恢复。

事务 journal schema 2 与安装清单 schema 2、统计块 schema 4 是三个独立格式。`Prepared` 持有可恢复的整组备份；回滚完整写回并刷新 `Restored` 后方可删备份；`Committed` / `Restored` 重启后只清理，不能再次要求已删除的备份。旧 `Committed=0/1` 日志仍可读取。清理中断、目录枚举错误、Flush/Replace 失败和跨进程锁竞争均在事务测试中注入，日志保留失败阶段及 Win32 错误。恢复状态以非阻塞 `ReadSaveRecoveryStatus` 发布为 Ready / RecoveryPending / CleanupPending；CleanupPending 不能把已确认的新存档说成失败，下一次存取先重试清理。

`SetSaveRecoveryReady` 控制持久化就绪状态，恢复失败不移除已经验证的 native guards。保存、读取、存档浏览器在进入原生操作前重试恢复，只有成功后才发布可用状态。保存写盘失败与真实统计历史缺失分开：前者不设置 `historyIncomplete`；旧档迁移或真正的读取/模型恢复缺损继续准确标记。读档失败不发布成功，也不覆盖原统计模型。

`BattleResourceSnapshot` 同时保存 profile、PID、创建时间、模块基址、process/resource generation、自有字符串、来源与诊断。`runtimeProfileReady`、`peopleLayoutReady`、`itemsLayoutReady`、`peopleReady`、`itemsReady` 各自独立；物品可读不能掩盖人物指针尚未加载。人物指针、内容、物品内容或代码身份改变会推进代次，复用旧地址的重新初始化也使旧快照失效。`IsBattleResourceSnapshotCurrent` 在异步发布和逐关导出前后复核；关联 R/S 使用同一份不可变快照。Protected220 的 provider 授权、实际表就绪、0x7B 条件扩展分别门控。

定向调用如下，`<BUILD_ROOT>`、`<FIXTURE_ROOT>` 必须替换为实际独立目录：

```text
<BUILD_ROOT>/66/SaveEnhancerTests.exe --extension-variant <FIXTURE_ROOT>/信奈15加1/Ekd5.exe
<BUILD_ROOT>/66/SaveEnhancerTests.exe --extension-variant <FIXTURE_ROOT>/信奈12/Ekd5.exe
<BUILD_ROOT>/66/SaveEnhancerTests.exe --extension-variant <FIXTURE_ROOT>/扩展66/Ekd5.exe
<BUILD_ROOT>/66/SaveTransactionsTests.exe
<BUILD_ROOT>/65/BattleRuntimeTests.exe --runtime-rva <CURRENT_RVA_IMAGE> <FIXTURE_ROOT>/加强版2.2.0
```

离线测试验证生产桥、文件事务和调用图契约；实际游戏中“保存、进程退出、重启、读取、统计字段对照”是独立门槛。本轮实机验收尚未完成，不能仅凭 `0 failures` 宣称用户基底已经可以保存。最终安装器、源清单和完整回归结果须绑定同一构建身份。

## 1.4.0 加壳容器与运行时公共层

`PeImage.h/.cpp` 分离 PeFileView、PeAnalysisView、RuntimeImageView。磁盘容器使用64位长度、有界读取和流式SHA-256；映像仍有64 MiB容量上限。虚拟节归属采用VirtualSize（为0时回退raw），节重叠/溢出拒绝，巨大的raw容器不会吞掉后续节。EngineSitePlan区分磁盘字节和RuntimeOnly，后者不能伪造文件偏移。

RuntimeImageView按真实分配与VirtualQuery边界捕获，保留可读/可执行范围，不读取guard/noaccess/未提交页。运行时操作数的实际加载基址与测试快照地址分离，Engine初始化采用Runtime源解析，并在捕获和写入前核对live原字节与页权限。

ProtectedRuntime按独立能力解析CreateFileA/W、TranslateMessage、DispatchMessageA/W、GetTickCount和SetTimer，交叉检查表、名称/OFT0指针、FF15调用关系及执行权限。虚拟文件包装器优先且必须唯一，不用系统CreateFile绕过VFS。CAS事务保留原指针、字节恢复和权限恢复状态；冲突保留恢复点，不覆盖第三方改动。恢复IAT后仍保留转发目标到进程结束，以支持已经进入wrapper的线程。

RuntimeStartupTracker在worker中每100ms观察，连续两次稳定才提交，15秒截止也检查当次新鲜结果，不能沿用陈旧能力。DllMain不执行扫描/哈希/模块初始化/IAT搜索写入；pending包装器透明转发。按功能初始化后更新Compatibility，安装本身只记Pending。RuntimeValidation=Passed表示身份、布局和已提交导入验证成功，不表示每个功能都Ready；缺失统计保存能力、名称资源或时钟入口分别降级。加壳启动的早期事件标为历史不完整。

完整构建使用Version.h统一1.4.0，安装器与代理包含Windows版本资源。发布资料需携带离线结果摘要与SHA-256；实机测试由用户负责，不能把静态大明检测通过写成实机通过。


## 1.4.1 Release：攻略 AI 与控制变化、加壳启动提示一次性化

攻略分析使用完整参数标签解码 `0x4E`，支持方针 0–7 和所有标准区域阵营。单人目标不依赖初始部署；`0x46/47` 只补充初始阵营说明，`0x4B` 的出战槽不作为 AI 目标的人物证据。方针未知时保留原始命令，区域使用脚本原范围，不以初始单位坐标冒充实际执行范围。

`0x77` 的 `[2,var,2,0,value]` 对整型变量直接赋常数，随后 `0x78` 的 `[var,1,person,32]` 写入人物行动方针。有限常量追踪按块树传递，并在分支汇合保留入口与出口一致的事实；未知覆盖、读取覆盖、调用和跳转使常量失效。写入按原生低字节处理，7为玩家可控，8为不可控，其他编码保留原值，不套用脚本方针表。动态人物、数值变量和未知标签有明确回退文本与带文件/Section/offset/block/event/ordinal的诊断。

公共解析器新增 `parentBlock`、`blockOwnerOrdinal`，原有编号与条件继承保持不变。攻略逐动作保存来源，按先后和父子路径关联对话，再进行同路径聚合；兄弟分支、跳转边界和对话前动作不能仅凭相同条件合并。对话与 AI 章节同时显示结果。子分支条件显示在对话之后；相同条件的子块单挑演出可归属父块对话，独立单挑也保留。奖惩复用同一动作来源，已合并奖励仍按原逻辑在完整视图去重。

`GuideAiFixtures.h` 是补丁与独立生成器的同源合成用例；内存测试入口运行完整分析流程。生成器由 `extract-core.py` 同步算法和公共解析器，`--check` 只读核对核心与来源哈希，普通独立源码构建不依赖 Python 或补丁仓库。作者攻略优先，旧的生成文本须重新导出才能体现变化。

加壳、受保护或版本回退构建的“尚未完全就绪”提示只在安装/更新补丁时由安装器报告一次；`Proxy.cpp` 在 `runtimeRequired` 为真时只写 `startup-notice-install-only`，不再弹出该提示。标准构建保持原有提示，清单/指纹/运行时入口等真正错误仍会提示。`RuntimeStartup.h` 的 `ShouldShowStartupReadinessNotice` 是纯策略函数，由 `RuntimeStartupTests` 覆盖；`InstallerProfileTests` 断言 packed 和版本回退安装报告包含 `【一次性提示】`、标准安装不包含。
